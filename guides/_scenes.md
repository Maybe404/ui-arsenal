# 场景规则：页面模式、效果预算和质量分级

所有选型指南共用这份规则。页面模式、craft-floor 的质量底线和动效时长来自 [impeccable](https://impeccable.style)（Apache 2.0），这里整理成中文并改写成选型规则；项目里装了 impeccable 时，以它为准。

## 1. 先判断页面模式

看的是**这个页面**要访客做什么，不看产品类别。同一个产品的落地页是 Persuade，它的后台是 Operate。

| 模式 | 典型页面 | 访客要做的事 | 视觉取向 |
|---|---|---|---|
| Persuade | 落地页、营销页、定价页、活动页 | 被说服，然后行动 | 可以有表现力，首屏允许一处主导效果 |
| Operate | 后台、dashboard、编辑器、设置、表单、工具 | 完成任务 | 克制、熟悉、一致；品牌只体现在细节 |
| Read | 文档、文章、帮助、更新日志 | 读懂内容 | 排版和导航优先，几乎不用特效 |
| Experience | 作品集、画廊、展示页 | 沉浸在作品里 | 作品本身是主角，界面退后 |

## 2. 效果预算

「主导效果」指 WebGL 或 canvas 背景、大型文字动效、光标特效、3D 物件这类会抢注意力的东西。

| 模式 | 主导效果 | 装饰动效 | 动效强度（1–10） | 密度（1–10） |
|---|---|---|---|---|
| Persuade | 首屏最多 1 个，整页最多 2 个，而且不在同一屏 | 每屏最多 1 处，必须有含义 | 4–7 | 3–5 |
| Operate | 0 个 | 只用于表达状态：加载、反馈、展开收起 | 1–3 | 6–9 |
| Read | 0 个 | 基本不用 | 1–2 | 4–6 |
| Experience | 1 个，为作品服务 | 少量 | 5–8 | 2–4 |

另外两条规则：
- 一页只能有一个主底座（见 `sources/_styles.md`）。专项组件不超过 2–3 个来源。
- 参考类来源（designspells、inspora、collectui、作品视频）只影响方向，不能当生产组件。

## 3. 默认取向（用户还没设置风格偏好时）

- 后台、工具、表单类页面：克制。能用主底座的组件就不用专项组件。
- 落地页和作品展示页：允许一处主导效果，其余保持克制。
- 同类候选打平时，选依赖更少、可访问性更完整、和主底座 token 更容易映射的那个。

用户以后设置了风格偏好，以用户的为准。

## 4. 质量三级

| 级别 | 内容 | 要求 |
|---|---|---|
| 1. 硬性问题 | 对比度不足（正文不到 4.5:1，大字不到 3:1）、焦点不可见或丢失、文字溢出或被遮挡、状态虚假（假进度、动画暗示一个其实没成功的操作）、动效让内容默认不可见、移动端不可用、触控目标太小、严重性能问题（动画改宽高、不限尺寸不暂停的 canvas 或 WebGL）、图片坏链、脚本报错 | **必须修**，没有例外 |
| 2. 设计系统偏差 | 颜色、圆角、字体、字号、阴影、密度、图标系统和设计基线不一致 | 必须修，或者在汇报里写明是有意的例外 |
| 3. 场景化审美风险 | 渐变文字、跑马灯、彩色光晕、网格背景、打字机光标、弹跳缓动、装饰性毛玻璃、脉冲圆点、用滥的字体（Inter、Geist 等作为展示字体） | **不禁止**。使用时在选型理由里写清场景；Operate 页面默认不用；Persuade 和 Experience 页面一处主导效果可以接受 |

注意：一个效果被判为第 3 级，不代表它就过关了。跑马灯要能暂停、遵守减弱动效设置；光晕和渐变文字不能拉低对比度。达不到就是第 1 级问题。

索引里每个条目的 `risk` 字段标的就是第 3 级风险，搜索结果里显示为 ⚠。

## 5. 动效规范

| 时长 | 用途 |
|---|---|
| 100–150 ms | 即时反馈：按下、切换 |
| 150–300 ms | 常规状态变化：悬停、展开、选中 |
| 300–500 ms | 布局变化、弹层、页面转场 |
| 500–800 ms | 精心设计的主导入场，整页只有一处 |

- 退出比进入快。
- 用自然减速曲线，比如 `cubic-bezier(0.16, 1, 0.3, 1)`；不要条件反射地用弹跳或回弹。
- 动效要表达含义：状态变化、反馈、连续性、揭示。每个区块都用同一种"淡入上移"不算动效设计。
- 必须遵守 `prefers-reduced-motion`：减弱时保留状态变化，去掉位移和装饰。
- 内容默认可见，动画只是增强。不能出现"动画没跑完，内容就看不见"的情况。
- 只动 `transform` 和 `opacity` 最稳。模糊、遮罩、clip-path 可以用，但要确认流畅；不要动画宽高、边距。

## 6. 常见的"AI 味"做法（第 2、3 级的高发区）

摘自 impeccable 的拒绝清单：
- 用同样大小的"图标 + 标题 + 一段话"卡片堆出整页结构；卡片里套卡片。
- 大数字配小标签的"英雄数据"模板。
- 标题上方的小号大写眉标（kicker）。
- 渐变文字；装饰性毛玻璃；卡片或提示框上超过 1px 的彩色左边框。
- 用 emoji 或 Unicode 字符代替图标系统。图标用一个库，粗细统一。
- 能用行内或渐进展开解决的事，却用了弹窗。
- 明暗按产品类别来定，而不是按使用场景来定。
